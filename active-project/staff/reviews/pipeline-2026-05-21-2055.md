## HARD findings

### STRUCT-012 — `/and-stitch` `$1` arg reads non-existent `active.episode` field

**file:** `.claude/commands/and-stitch.md` line 78

**what:** `$1 — optional. Episode slug (e.g. s01e01). If omitted, use active.episode from active-project/staff/showrunner/memory.md.`

**why HARD:** `active.episode` does not exist in `schemas/showrunner-memory.schema.md`. The `active:` block defines `book: b01 | null`, `chapter: b01c01 | null`, and `cascade_in_progress: true | false`. No `episode:` field is present. A stitcher fork invoking `/and-stitch` without an explicit slug would attempt to read `active.episode` from memory and find nothing; the fallback would either fail silently or abort. The example slug `s01e01` is also pre-substance vocabulary — under the current chain, chapter slugs are `b01c01` form.

**criteria:** The `$1` description must reference `active.chapter` from `active-project/staff/showrunner/memory.md` (not `active.episode`). The example slug should be updated to a substance-chain form (e.g. `b01-c01`).

### STRUCT-013 — `schemas/stitch-profile.schema.md` `boundary-source` enum still lists `tensometer-derive` as a valid value

**file:** `schemas/stitch-profile.schema.md` line 70 (profile structure) and line 216 (field rules for `scene-window.boundary-source:`)

**what:** Profile structure (line 70):
```yaml
boundary-source: scene-map-facet        # scene-map-facet (default) | tensometer-derive | hybrid
```
Field rule (line 216): describes `tensometer-derive` as parsing "the scene-footer section of `tensometer-<slug>.md` plus cross-references `interest-narrator.md` sparsity gradient" and `hybrid` as reading scene-map-facet with tensometer-derive fallback.

**why HARD:** `/and-stitch.md` Phase 1 scene-window § Scene-boundary resolution step 2 (line 368) explicitly states: "Tensometer derivation (REMOVED 2026-05-17 under URI-SUBSTANCE-OVERHAUL). The tensometer-fallback path is dead code under the new chain." The schema still enumerates `tensometer-derive` as a valid enum value. A stitcher fork that reads the profile schema as its authority and sets `boundary-source: tensometer-derive` would attempt to parse a `tensometer-<slug>.md` file that is never written by the current chain. Schema-vs-command-body drift on a dead code path that can silently mis-dispatch Phase 1.

Also at line 216: the field rule says the default path emits via "`/and-facets` Phase 4d as derived structural facet" — directly contradicting STRUCT-005's fix (which established `/and-write` Phase 7 emits the scene-map and `/and-facets` Phase 4d validates only). See STRUCT-020 for the validation-vs-derivation drift.

**criteria:** Remove `tensometer-derive` and `hybrid` from the `boundary-source` enum (line 70 and line 216 field rule). Remove the `tensometer-derive` path description from the field rules. Update the field rule's description of `scene-map-facet` to credit `/and-write` Phase 7 as the emitter (not `/and-facets` Phase 4d).
