# Dark-Fantasy Reader — State-Updates Adversarial Verdict

## Stance

Consequence that propagates. State-updates is the layer where the world records what happened — where the cost gets filed. If the entries don't track real terrain costs, they're decorating a set, not mapping a world that was there before the protagonists arrived. I'm looking for: does the canonical state-record honor what actually moved? Does anything get written in that should stay unwritten?

**[state-updates:4] @12 taylor.capability_axis: 2 -> 3**

Two entries fire at @12. The question is whether these are two genuinely distinct fields or whether one is parasitic on the other.

Deployment-state (state:3) tracks the operational posture — passive vs. active, the mode of the network. Capability_axis (state:4) tracks the rank-tier — the system's demonstrated scope and capacity. These are distinct aspects. A character can have a high capability rank while holding passive deployment-state (Taylor at the start of the chapter: capability suppressed at rank 2 subsistence, deployment passive). After @12: capability rank rises to 3 (one deployment completed; the system's capacity is now demonstrated) AND deployment-state is active. Both are real field-changes.

But here is my problem: `capability_axis` as a field on the actor's state.md is the substance-system's axis rank number being written into canonical actor state. The substance axes live in showrunner memory — that is their home. When the impersonator fork writes `capability_axis: 2 -> 3` into the state-updates facet, it is writing a showrunner-memory value into what should be the actor's own state record. The actor's state.md tracks where the character is, what they carry, what they know, what their operational status is. The axis rank is a frame put on the actor by the substance system — it lives in showrunner memory as the substance_delta measurement, not in the actor's own state.

If `active-project/actors/taylor-hebert-kl-122ac/state.md` contains a `capability_axis` field, this is legitimate. If it doesn't — if capability_axis is only in showrunner memory's substance_delta — then this entry is writing substance infrastructure into the actor's canonical state file where it has no home. The showrunner would apply this as a mutation to a field that doesn't exist.

The world needs to record that something changed at @12. State:3 (deployment-state) does that. Whether it also needs a separate axis-rank entry depends entirely on whether that field is real in the actor's schema.

**`FLAG: [state-updates:4] @12 — capability_axis field-on-schema unverified. If it exists on actor:taylor state.md, CORRECT. If not, anti-pattern #6 — substance rank written into actor state without a home.`**
